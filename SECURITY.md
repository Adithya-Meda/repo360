# Security Policy

## Supported Versions

Only the latest release receive security patches and updates.

| Version | Supported          |
| ------- | ------------------ |
| 1.1.x   | :white_check_mark: |
| < 1.1.0 | :x:                |

## Reporting a Vulnerability

The Repo360 engineering team takes the security of platform governance tooling seriously. If you discover a vulnerability, please report it responsibly rather than opening a public issue.

### Preferred Reporting Method
Submit an advisory via **[GitHub Private Vulnerability Reporting](https://github.com/Adithya-Meda/repo360/security/advisories/new)**.

### Alternative Reporting Method
If you cannot use GitHub Security Advisories, send an encrypted report to:
* **Security Contact:** `47377931+Adithya-Meda@users.noreply.github.com`

### What to Include
Please provide:
* Detailed description of the vulnerability and attack vector.
* Minimal steps or script to reproduce the issue.
* Potential impact on credentials, tokens, or audit data.
* Any proposed mitigations or remediations.

### Coordinated Disclosure Process
1. **Acknowledgment:** We aim to acknowledge receipt of the report within 48 hours.
2. **Assessment:** We will confirm the issue, assess severity, and keep you informed of remediation progress.
3. **Patch & Release:** A patched release will be published to PyPI and GitHub Releases.
4. **Public Disclosure:** An advisory will be published with credit given to the finder (unless anonymity is requested).
