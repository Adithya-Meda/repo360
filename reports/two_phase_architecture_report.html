Repo360 Engineering Architecture Report

PRODUCTION READY TWO-PHASE ARCHITECTURE ZERO RATE LIMITS
Scope: Full Platform Scale Hardening (Audit, DORA, FinOps, Bypass) | Python 3.12 Architecture | Author: Senior Platform Engineer

Executive Summary & Problem Statement

When running Repo360 against large enterprise organizations (500 to 20,000+ repositories), the previous architecture allowed worker threads to invoke AI remediation and flow diagnosis tasks concurrently during active repository scraping. Even with adaptive worker pools, submitting individual tasks per failed check or per repository flooded LLM provider APIs (such as Google Gemini free/tier-1 quotas at 15 RPM).

This led to:

  • Upstream HTTP 429 Quota Exhaustion: Free-tier rate limits were tripped after only 3–4 calls, activating the circuit breaker cooldown (120s) and falling back to deterministic templates.
  • Thread Contention & Starvation: The background executor competed with network I/O threads, leading to wait timeouts (e.g. 180s timeout warnings).
  • Redundant LLM Calls: Identical findings (e.g. missing CODEOWNERS for Python) were evaluated independently hundreds or thousands of times.

The Solution: A unified Two-Phase Staged Architecture implemented across all four core features (audit, dora, finops, bypass).

Architecture Blueprint: Two-Phase Staged Pipeline

Phase Audit Pipeline DORA Pipeline FinOps Pipeline Bypass Pipeline
Phase 1: Pure Scraping High-concurrency thread pool scans trees, rulesets, and checks. Zero AI calls. Tech stacks attached to result. GraphQL & deployment collection across repos with zero inline AI overhead. Disk and artifact quota calculation across repos with zero inline AI overhead. Alerts gathered with deterministic baseline risk/advisory. Zero inline AI calls.
Phase 2: Canonical Deduplication Findings clustered by (check_id, canonical_stack). Non-code languages collapsed. Repos clustered by flow signature (overall, df_tier, lttc_tier, cfr_tier, mttr_tier, rework, signal). Storage profiles clustered by (optimization_status, default_90d, stale_cache, size_tier). Bypasses clustered by (secret_type, resolution_comment).
Phase 3: Targeted Synthesis & Fan-out AI called once per uncached key (bounded to 30). Snippet fanned out in-memory to all matching findings. AI diagnoses representative flow once. Advisory fanned out to all matching repos with slug adaptation. AI synthesizes storage advice once. Advisory fanned out to all matching repos with slug adaptation. AI assesses risk/advisory once. Output fanned out to all matching bypass records.

Before vs. After Code Implementation

1. Audit (`src/repo360/main.py`)

Before: In-flight AI Executor During Scraping
# Inside _audit_single_target:
if ai_executor and is_ai_live(ai_engine):
    pending_ai_items.append((res, dict(tech_stack)))

# Loop submitting thousands of futures:
for res_item, stack_item in pending_ai_items:
    fut = ai_executor.submit(
        ai_engine.enrich_remediation, res_item, stack_item
    )
    ai_futures.append(fut)

# 180s blocking drain wait loop causing timeouts
After: Pure Scraping + Post-Audit Deduplicated Fan-Out
# Phase 1: Pure scraping (no background AI executor)
res.extra_details["_tech_stack"] = dict(tech_stack)
repo_res.append(res)

# Phase 2: Post-audit unique canonical clustering
unique_groups = {}
for res in results:
    if ai_engine.is_eligible_for_remediation(res):
        key = ai_engine.get_remediation_cache_key(res.check_id, stack)
        unique_groups.setdefault(key, (res, stack, [])).append(res)

# Phase 3: Targeted synthesis & 100% memory fan-out
uncached_keys = [k for k, v in unique_groups.items() if not cached(k)]
run_concurrent_ai(uncached_keys[:30], _synthesize_key)
# All 5,000+ matching results instantly AI-enriched in memory

2. DORA Metrics (`src/repo360/dora/collector.py`)

Before: 1 AI Call Per Active Repository
ai_items = []
for m in metrics_list:
    if m.total_deploys > 0:
        ai_items.append((idx, m, ...))

# Flooding LLM with hundreds of duplicate metrics
run_concurrent_ai(
    ai_items,
    lambda item: ai_engine.diagnose_dora_flow(...),
    max_workers=8
)
After: Signature Grouping + Slug-Aware Fan-Out
# Group by delivery archetype:
sig = (overall, df_tier, lttc_tier, cfr_tier, mttr_tier, rework, signal)
unique_dora_groups.setdefault(sig, []).append(item)

# Synthesize representative item once per flow pattern:
unique_recs = run_concurrent_ai(rep_items, _diagnose_rep)

# In-memory fan-out with dynamic slug adaptation:
for (sample_org, sample_repo, adv), s in zip(unique_recs, unique_sigs):
    sample_slug = f"{sample_org}/{sample_repo}"
    for member in unique_dora_groups[s]:
        target_slug = f"{member.org}/{member.repo}"
        ai_advisories[member.idx] = adv.replace(sample_slug, target_slug)

3. FinOps Storage (`src/repo360/finops/collector.py`)

Before: 1 AI Call Per Unoptimized Repository
ai_items = []
for p in profiles:
    if not is_baseline_optimized:
        ai_items.append((idx, p, stale_cache_count))

run_concurrent_ai(
    ai_items,
    lambda item: ai_engine.generate_finops_advisory(...)
)
After: Optimization Profile Clustering
# Group by storage waste signature:
sig = (p.optimization_status, p.default_90d > 0, stale > 0, disk > 1GB)
unique_finops_groups.setdefault(sig, []).append(item)

# Synthesize once per unique storage profile archetype:
unique_recs = run_concurrent_ai(rep_items, _diagnose_finops)

# Fan out tailored advisory to all matching repositories:
for (sample_org, sample_repo, rec), s in zip(unique_recs, unique_sigs):
    sample_slug = f"{sample_org}/{sample_repo}"
    for member in unique_finops_groups[s]:
        target_slug = f"{member.org}/{member.repo}"
        rec_by_idx[member.idx] = rec.replace(sample_slug, target_slug)

4. Push Protection Bypass (`src/repo360/bypass/collector.py`)

Before: Synchronous Inline Calls During Scraping
# Inside parse_push_protection_alert during network fetch:
if ai_engine is not None:
    risk, advisory = ai_engine.analyze_push_protection_bypass(...)

# Followed by a second pass over all_push_records:
run_concurrent_ai(all_push_records, _enrich_push)
After: Pure Scraping + Post-Collection Clustering
# Phase 1: Pure parsing with deterministic baseline (no AI)
risk = "Moderate Risk"
advisory = f"Push protection was bypassed by {actor}."

# Phase 2 & 3: Post-collection deduplication by (secret_type, comment)
sig = (rec.secret_type.lower(), rec.resolution_comment.lower())
unique_bypass_groups.setdefault(sig, []).append(rec)

unique_assessments = run_concurrent_ai(rep_records, _diagnose_bypass)
for (sample_repo, risk, adv), s in zip(unique_assessments, unique_sigs):
    for member_rec in unique_bypass_groups[s]:
        member_rec.ai_risk_assessment = risk
        member_rec.ai_security_advisory = adv.replace(sample_repo, member_rec.repo)
